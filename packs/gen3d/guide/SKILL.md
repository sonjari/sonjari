# 손자리 3D 생성 팩 — 클로드용 사용서

손자리는 사용자 PC 의 그래픽카드로 **그림 한 장 → 3D 초안(GLB)**을 굽는다(trellis.cpp · TRELLIS.2 8비트 · 512 는 12GB 카드에서 보통 1분 반~2분 반).
나누는 원칙: **뜻(무엇을 · 어떤 그림으로)은 당신이, 재기 · 굽기 · 숫자는 손자리가.** 결정 기록: `docs/ADR_3D입력판정_2026-11-14.ko.md`.

| 당신(클로드) | 손자리 |
|---|---|
| 사람이 원하는 것(프린트 · 게임 · 보기)을 묻고 길을 정한다 | `gen_3d_check` — 그림을 잰다(물체 수 · 선만 있나 · 잘림 · 바탕) |
| 필요하면 3D 에 맞는 그림을 SVG 로 다시 그린다 | `gen_3d` — 굽는다(한 번에 하나) · 앱 무대에 자라나는 모습을 보인다 |
| 영수증 · 미리보기를 원본과 대조하고 다음 칸을 정한다 | `gen_3d_status` — 단계 · 영수증(면 수 · 크기 · 메모리 · 걸린 초 · 프린트 판정) |
| 사진의 지울 칸을 격자에서 고른다 | `gen_3d_prep` — 키우기 · 격자 그림 · 칸 지우기 · 전후 그림 |
| 6방향 판을 원본과 대조해 판을 고른다 | `gen_3d_views` — 앞 · 뒤 · 좌 · 우 · 위 · 아래 한 장(굽기 끝나면 저절로도) |
| 조명 있는 색 그림(영상 첫 장면 · 사람에게 보일 것) | 굽기 영수증 `files.beauty`(앞 · 3/4 · 블렌더 Cycles CPU) · 옛 판은 `gen_3d_views` source=beauty. 블렌더가 없으면 not_done 에 까닭. 「새까맣다」는 텍스처 바탕색이 검정인 판 — 조명으로 안 풀린다 |
| 전후 모양 판을 보고 줄무늬가 줄었는지 · 살릴 새김이 남았는지 판단한다 | `gen_3d_finish` — 블렌더 마무리(기본: 모양 지키며 겉면 펴기 8번 · `finish_v<n>/` · 원본 그대로 · 전후 판 · 이동량 · 부피) |
| 영상 팩에 넘길 진짜 3D 그림 · 한 바퀴(첫/끝 그림 · 광고 컷 · 시연) | `gen_3d_render` — still(스튜디오 컷 한 장 · 85mm) · turntable(한 바퀴 PNG + mp4) · look=clay(회색 형체). Cycles CPU · `render_v<n>/` · 숫자는 파일에서 잰 것(크기 · 장 수 · 모델 몫 · 이음새 멈칫). 영상 크기에 맞춰 width · height(예 832×480) · 광고면 background=#000000. 그림은 열어 본다 |
| 프린트 영수증을 읽고 크기 · 방향 · 세밀도를 고쳐 다시 시킨다 | `gen_3d_print` — 다시 굽지 않고 프린트 파일만 다시(1분 안팎 · `print_v<n>/` · `floor_cut_mm`) |
| 나눠 뽑을지 · 어디를 나눌지 정한다(이음매 · 색 · 받침) | `gen_3d_split_plan` — 나눌 자리 후보 · 번호 그림 / `gen_3d_split` — 자르기 · 핀 구멍 · 핀 · 판 · 썰기(`split_v<n>/`) |
| 사람에게 끼움 시험 조각을 뽑게 하고, 고른 틈을 받아 적는다 | `gen_3d_fit_test` — 구멍 다섯 막대 + 핀 / `gen_3d_fit_set` — 틈 저장 |

## 1. 순서 — 싼 길부터, 결과로 한 칸씩 올린다

1. **사람의 목적을 안다.** 프린트(크기 mm) · 게임(리깅할 캐릭터인가 소품인가) · 그냥 보기. 모르면 한 번만 묻는다.
2. **`gen_3d_check` 로 잰다.** `blocked` 가 있으면 그 그림으로는 못 만든다(이유를 그대로 전한다).
3. **길을 고른다** — 아래 표. 원칙 한 줄: **원본이 그 사람의 것(직접 그린 그림 · 사진)이면 그대로 먼저, 원본이 재료일 뿐(낙서 · 설명)이면 당신이 다시 그린다.**
4. **`gen_3d`** → 앱에 무대가 뜬다. `gen_3d_status` 는 1~2분 뒤에 부른다(자주 부르지 않는다).
5. **결과를 근거로 본다.** 영수증 숫자 + 미리보기 webp 를 원본과 대조(돛 수 · 팔 개수 · 얼굴 느낌). 나쁘면 표의 「승급」 칸으로 한 칸 올린다. 같은 칸을 씨앗만 바꿔 되풀이하는 것은 한 번까지.

## 1-0. 사진 · 그림 한 장 → 「두 번 굽기」 분업 (11-15 리락쿠마 · 설계 `docs/설계_3D두번굽기_분업_2026-11-15.ko.md`)

**손자리는 눈과 손, 당신은 판단.** 무거운 일(손질 · 굽기 · 찍기 · 재기)은 손자리, 당신은 「무엇을 · 왜」만.

1. **먼저 말한다:** 「사진 한 장 피규어는 보통 두 번 굽습니다(초안 → 고쳐서 다시) · 한 판 PC 2~3분 / 맥 10분」. 목적 · 크기 · 지울 것(열쇠고리 구멍 · 스티커)을 한 번만 묻는다.
2. **`gen_3d_check`** → 작은 사진(짧은 변 < 512) · 지저분한 바탕이면 **`gen_3d_prep`**(키우기 + 격자 그림).
   - 지울 칸은 **반드시 격자 그림을 보고**(작은 건 grid 32~48 + view 확대) 고른다 — 머릿속 계산은 빗나간다(11-15 오른쪽 볼).
   - **꼭 필요한 작은 칸만:** 열쇠고리 구멍 · 반사 점은 fill. 넓은 칸 메우기 · 전체 펴기(smooth)는 얼굴을 우글거리게 하고 작은 눈 · 코를 지운다(11-15 실측).
   - 바탕은 실행기가 지운다 — 배경을 네모로 칠하지 않는다(딱딱한 경계가 남음). 몸에 딱 붙어 딸려 온 배경 덩어리만 bg.
   - `before_after` 를 보고 손질본(image)을 쓴다. 사람의 원작 그림은 손대기 전에 묻는다.
3. **`gen_3d` 를 씨앗 다르게 2~3판**(seed 값만 바꿈). 같은 그림이어도 **뒤 · 바닥은 씨앗 운이 크다**(11-15: 셋 중 하나만 뒤 · 바닥이 매끈).
4. **`gen_3d_views`(6방향 판)로 판마다 본다** — 앞 · 뒤 · 왼쪽 · 오른쪽 · 위 · 아래. 원본과 대조: 흠 · 딸려 온 배경 · 안 보이던 쪽(엉덩이 · 등 · 바닥). 가장 나은 판을 고른다.
   **판단은 모양 판(`_shape_views.png` · `source="shape"` · 회색)으로** — 색 판은 색 확인용이다. 색이 모양을 가린다(11-15: 색 판에선 햄버거 층이 좋아 보였는데 모양은 매끈한 통이었다).
5. **2차 길(판단표):**

| 6방향 판에서 | 탓 | 다음 |
|---|---|---|
| 앞에서 보이는 흠(점 · 고리 · 반사) | 사진 | `gen_3d_prep` 작은 칸 더 → 다시 굽기 |
| 얼굴 · 작은 부분 뭉개짐 | 사진이 작음 | 크게 자른 손질 · `res: 1024` |
| 뒤 · 엉덩이 · 바닥 엉망 | 안 보이던 쪽 | **씨앗 다르게 더** → 그래도면 바닥 자르기 |
| 겉면에 가로 계단 줄무늬(회색 판에서 잘 보임) | 굽기 뒷단계(다시 뜨기 · 면 줄이기) 자국 — 11-15 공개 원본 대조 | 매끈한 겉(곰 · 개구리 · 장난감)이면 `gen_3d_finish` 기본(펴기 8번) → `before_after` 판을 본다. **털 · 결이 있는 겉은 전체 펴기 금지** — 아래 §1-3 표 |
| 바닥이 점처럼 닿음(영수증 `needs_decision`) | 둥근 바닥 | `gen_3d_print(floor_cut_mm=영수증 floor_suggestion.cut_mm)` — 아래가 깎인다고 말하고 |
| 가는 곳 · 받침 많음 · 판보다 큼 | 프린트 | `gen_3d_print`(크기 · 방향) · `gen_3d_split` |

6. 영수증 `report.steps`(다시 뜨기 · 면 줄이기 · 받침 · 썰기의 초 · 숫자)와 `needs_decision` 을 읽는다. 굽는 중엔 `gen_3d_status` 의 `print_step` 이 지금 단계다.
7. 그래픽카드는 손자리가 남은 메모리가 큰 카드를 고른다(영수증 `gpu_pick`). 사람이 번호를 주면 그대로.
8. 사람에게는 마지막에 6방향 판 · 시간 · 무게 · 깎인 곳을 보여 주고 출력 여부를 묻는다.

## 1-1. 프린트 폐루프 — 한 바퀴씩 싼 것부터 (11-14 첫 출력 배에서)

```
목적 · 크기 ─▶ gen_3d_check ─▶ (그림 다시?) ─▶ gen_3d(export stl·3mf · size_mm · printer)
     ▲                                                     │
     │                                            gen_3d_status 영수증
     │                                                     │
     │    ┌── 그림이 문제(얇은 곳이 그림 탓 · 모양이 틀림) ── SVG 다시 그림 → gen_3d   (몇 분)
     └────┼── 크기 · 방향 · 세밀도가 문제 ───────────────── gen_3d_print            (1분)
          └── 통과 ─▶ 사람이 뱀부 스튜디오에서 「플레이트 슬라이스」 확인 → 출력 시작(사람)
                                       │
                         출력 결과(사진 · 걸린 시간 · 실패한 자리)를 사람에게 받아 다음 판에 반영
```

한 바퀴마다 영수증에서 볼 것과 다음 칸:

| 영수증에서 | 뜻 | 다음 칸 |
|---|---|---|
| `printable.ok` false | 닫힌 메시를 못 만듦 | `why` 그대로 전하고 그림을 다시(큰 구멍 · 잘린 그림) |
| 메모 「가는 막대를 굵게 했다」 | 길고 가는 막대(밧줄 · 돛대)를 1.6mm 로 굵힘(11-14 실물: 1mm 밧줄이 털 · 구슬로 망가짐) | 그림보다 굵어졌다고 전한다. 얇은 판(벽 · 돛 · 깃발)은 그대로 둔다 |
| `remesh.thin_share` > 0 · `thin_bbox_mm` | 굵히고도 1.2mm 보다 가는 길쭉한 곳 | **크기를 키워도 되면** `gen_3d_print(size_mm 더 크게)` · 안 되면 그 자리를 굵게 다시 그림 |
| 받침이 떼기 힘든 자리(오목한 안쪽 · 돛 아래)에 크게 붙음 · 판보다 큼 · 색이 둘 이상 | 통째로 뽑기 불리함 | **나눠 뽑기**(1-2) |
| `plan.decisions` 의 `orientation` | 다른 방향이 받침을 크게 줄임(제안만) | 사람에게 보이는 면이 바뀐다는 말과 함께 묻고, 받아들이면 `gen_3d_print(orientation=…)` |
| `simplify` | 면 줄이기(닫힘 · 오차 0.05mm 지킴) | `faces_after` · `used.max` 를 전한다. 「그대로 둔다」 메모면 뱀부가 느릴 수 있다고만 |
| `slice.estimated_time` · `filament_g` | 뱀부가 잰 시간 · 무게 | 그대로 전한다(지어서 반올림하지 않는다) |
| `slice.notes` 「다시 썰면 실패」 | 명령줄 재확인 실패(원인 조사 중) | 뱀부 화면에서 「플레이트 슬라이스」로 확인하고 출력하라고 |

규칙:
- **싼 바퀴부터.** 크기 · 방향 · 세밀도로 풀리면 `gen_3d_print`(1분), 모양이 틀렸을 때만 다시 굽는다(몇 분).
- **한 바퀴에 하나만 바꾼다.** 크기와 방향을 같이 바꾸면 무엇이 효과였는지 모른다.
- **앞 판은 지우지 않는다.** `print_v1` · `print_v2` … 를 견줘 사람에게 고르게 한다.
- **출력은 사람이 누른다.** 손자리 · 당신 누구도 프린터로 보내지 않는다. 출력 뒤 결과(사진 · 시간 · 실패 자리)를 물어 다음 판의 근거로 쓴다.

## 1-2. 나눠 뽑기 — 조립 부품 (11-14 · 설계 `docs/설계_조립부품나누기_2026-11-14.ko.md`)

**당신은 「어디를 왜」만 정하고, 숫자는 손자리가 낸다.** 좌표 · 지름 · 깊이를 지어내지 않는다.

1. **틈을 아나?** 영수증 `clearance_from` 이 「안 잼」이면, 첫 조립 모델 전에 `gen_3d_fit_test` 로 시험 조각(약 10분 출력)을 뽑게 권한다.
   사람이 「0.15 가 딱」이라고 하면 그 말 그대로 `gen_3d_fit_set(clearance_mm=0.15, note=사람 말)`. 짐작으로 넣지 않는다.
2. **`gen_3d_split_plan(job_id, size_mm)`** → 후보 목록 + 그림 셋(앞 · 옆 · 위, 빨간 선 = 후보 번호). **그림을 연다.**
   - 종류: **목**(잘록한 곳 · 곰 목) · **밑동**(귀 · 팔 · 돛대 같은 가지가 몸에 붙는 곳) · **갈래**(몸통에서 여러 가지가 나뉘기 바로 앞 · 배 갑판).
   - 고르는 기준: ① 받침이 떼기 힘든 곳이 사라지나 ② 이음매가 보기 좋은 자리인가(목 아래 · 귀 밑동 · 옷 경계) ③ 색이 바뀌는 경계인가(갈색 몸 · 흰 주둥이 → 따로 뽑으면 여러 색 장치 없이 두 색) ④ 부품이 판에 들어가나.
   - 너무 잘게 나누지 않는다(보통 2~5조각). 작은 귀 · 손가락은 핀 자리가 없어 접착이 된다.
3. **`gen_3d_split(job_id, cuts=[{candidate: 번호, name: 「목」}], size_mm)`** — split_plan 과 **같은 size_mm · orientation**.
4. 영수증에서 사람에게 전할 것:
   - 부품마다 `lay`(어느 면을 판에) · `overhang_mm2` 와 `overhang_if_upright_mm2`(세운 채와 견줘 받침이 얼마나 줄었나)
   - `pins`(지름 · 길이 · 몇 개) · `notes` 의 「핀 자리가 없다 — 접착」 · 「핀 하나 — 돌 수 있어 접착 같이」
   - 판마다 `slice.estimated_time` · `filament_g` · 판 장수 · `assembly_steps`(조립 순서) · 조립 그림(`*_assembly_front.webp`)
   - `clearance_from` — 틈을 잰 값인지 기본값인지
5. 나쁘면: 핀이 없으면 다른 후보(단면이 넓은 쪽) · 부품이 판보다 크면 하나 더 자르기 · 받침이 그대로면 다른 자리. **한 바퀴에 하나만 바꾼다.**

11-14 실측(배 · 갑판 「갈래」에서 나눔): 선체를 뒤집어 갑판 면을 판에 → 선체 받침 1,293 → 58mm² · 판 하나 2시간 7분(통째로 2시간 52분).

**따로 구운 부품 끼우기(`attach` · 11-16 · 설계 §8-6).** 디테일 때문에 따로 구운 부품(햄버거)을 바탕(곰 몸)에 레고처럼 끼운다.
- `gen_3d_split(job_id=바탕, cuts=[...], attach=[{job_id: 햄버거 판, size_mm: 39, from: "front", at: "auto", depth_mm: 2, onto: 2, name: "햄버거"}])`
- `from` = 어느 쪽에서 밀어 넣나(top · front · back · left · right · 앞 = -y). **머리가 몸보다 큰 인형은 top 이면 머리에 닿는다** — 배 앞 · 무릎은 front.
- `at` = top 이면 [x 가운데, y 가운데], front/back 이면 [x 가운데, z 바닥 높이], left/right 면 [y 가운데, z 바닥 높이] (mm · 바탕 프린트 자리).
  모르면 `"auto"`(맞닿는 넓이가 가장 큰 자리). 좌표는 지어내지 말고 영수증 `files.seat_maps` 자리 지도(10mm 눈금)를 보고 고친다.
- `onto` = 홈을 팔 바탕 부품 번호(같은 cuts 의 앞 영수증 번호 · 목에서 자르면 ＋쪽 머리 1 · －쪽 몸 2). 주면 그 부품만 보고 민다(머리는 나중에 얹으니).
- 전할 것: `attached[].socket_mm2`(홈 넓이) · `depth_mm` · `pin`(지름 · 길이 · 없으면 「홈 + 접착」) · `floor_min_mm` · 판마다 시간 · 무게(앉힌 부품은 **다른 판** = 다른 색 필라멘트) ·
  `*_seated_front.webp`(다 끼운 모습) · `seat_*.png`(홈 자리 빨강 · 핀 원).
- 거절(그대로 전하고 자리 · 깊이를 바꿈): 홈 아래 살 < 1.6mm · 바탕이 갈라짐 · 다른 부품(머리)에 박힘 · 모형 밖.
- 11-16 실측(곰 80mm + 햄버거 39mm · front · auto): 손끝 두 곳에만 닿아 홈 72mm² · 핀 3mm — 이 곰은 손이 배 앞으로 나와 무릎 받침이 없다. 홈이 작으면 접착을 같이 권한다.

## 1-3. 겉면 펴기 — 「이렇게 했더니 이렇게 됐다」 실측 표 (11-15 · 11-16 · 고칠 때마다 줄을 더한다)

횟수는 감으로 정하지 않는다. **겉의 종류로 먼저 가르고**, 판을 보고 확인한다. 줄무늬 숫자 잣대는 아직 없다 — 판단은 `before_after` 판(사람 눈 · 클로드 눈).

**규칙(표에서 나온 것):**
- **매끈한 겉 → 8번.** 3번은 모자라고 30번은 새김을 지운다.
- **털 · 결이 있는 겉 → 전체 펴기 하지 않는다.** 줄무늬와 털결이 크기가 비슷해 **횟수를 줄여도 둘을 못 가른다**(4번에서도 털결이 지워짐). 줄무늬가 꼭 거슬리면 그 자리만 `box` 로.
- 확인은 늘 `before_after` 판: 「줄무늬가 남았나」 · 「입선 · 눈 · 털결이 지워졌나」 둘을 본다. 지워졌으면 `base: original` 로 돌아가 펴지 않거나 `box` 로.
- **새 모델에 걸어 본 결과는 이 표에 한 줄로 더한다**(모델 · 겉 · 횟수 · 본 것 · 영수증 숫자). 표가 쌓여야 기본값을 바꿀 근거가 된다 — 3판 미만으로 기본값을 바꾸지 않는다.

## 3. SVG 로 다시 그릴 때 — 11-14 실측에서 나온 규칙

- **물체 하나 · 가운데 · 빈(흰) 배경 · 3/4 시점.**
- **색면과 부드러운 명암**으로 부피를 보인다. 선만 그리면 선이 철사로 나온다(배 낙서: 큰 돛이 테두리만).
- ★ **명암은 꼭 넣는다(11-17 실측).** 단색 칸만 붙인 아이콘 로봇은 씨앗 다섯 번 모두 「흰 판에 붙은 검은 부조」로 나왔고(판이 생기고 색이 판으로 감 · 금속도 0.4~0.8), 같은 로봇에 둥근 방사 그러데이션 명암(밝은 쪽 왼쪽 위 · 가장자리 어둡게)만 넣자 한 번에 입체 · 제 색이 나왔다. TRELLIS 관리자도 같은 증상에 「학습 데이터 속 평면 2D 그림 탓 · 3D 렌더처럼 보이게 바꿔 넣어라」라고 답했다(github.com/microsoft/TRELLIS.2/issues/45). 리락쿠마 SVG 가 된 까닭도 이 명암이다.
- 팔다리가 몸에서 떨어져 보이면 `several_objects` 로 걸린다 — 어깨 · 엉덩이에서 살짝 이어 그린다.
- 아주 가는 선 · 작은 글자 · 실 같은 장식은 피한다. 밧줄 정도의 두께는 나온다.
- 캐릭터: A자 · 정면 · 팔다리와 몸 사이를 띄운다(붙어 있으면 3D 에서도 붙는다).
- SVG 를 PNG(긴 변 1024)로 바꿔 사용자 PC 에 저장하고, 그 경로를 `gen_3d` 에 준다.

### 프린트할 것이면 처음부터 프린트용으로 그린다 (11-14 첫 출력 배에서)

크기(mm)를 먼저 정하고, 그 크기에서 아래가 지켜지게 그린다. 3D 로 만든 뒤 고치는 것보다 그림에서 고치는 것이 싸다.
- **가장 가는 곳도 1.2mm 이상**(노즐 0.4 × 세 줄). 100mm 배라면 밧줄 · 돛대 · 깃대는 그림 폭의 1.2% 이상 굵게.
- **바닥이 평평한 면 하나.** 둥근 배 밑 · 공 같은 발이면 받침(대좌)을 같이 그린다. 둥근 바닥은 판에 점으로 닿아 서포트 발이 붙는다.
- **허공에 뜬 가는 줄 · 끝이 떨어진 장식은 몸에 붙인다.** 돛 끝 밧줄처럼 한쪽만 붙은 가는 줄은 서포트가 높게 따라 선다.
- 아래로 넓어지는 모양(T 자 · 버섯)이면 뒤집어 놓을 수 있는지 사람에게 묻는다 — 영수증의 방향 제안을 본다.
- **색으로만 그린 무늬(볼터치 · 그라데이션 점)는 지운다.** 한 색 출력에선 모양으로 안 남고 얼굴에 울퉁불퉁한 흠만 남긴다(11-16 리락쿠마 볼터치). 색이 꼭 필요하면 따로 부품으로.
- **작은 얼굴은 선 · 점이 아니라 볼록한 덩어리로.** 점 눈 + 입선은 웃는 얼굴로 읽혔다 → 볼록한 주둥이 + 코 + 큰 눈으로 그리니 곰 얼굴로 나왔다(11-16 햄버거 v3 → v4 · n=1).
- **작은데 디테일이 중요한 부분은 그 부분만 따로 그려 따로 굽는다** — 512 칸이 그림 전체에 나뉘기 때문(조립 설계 §8 · 실측 진행 중).

## 4. 영수증 읽기 — 숫자는 영수증에서만

- `measured`: 면 수 · 메운 구멍 · 떼어 낸 조각 · 크기 · 그래픽카드 메모리 · 걸린 초. 사람에게 숫자를 말할 때는 여기서만 옮긴다.
- `printable.ok` 가 false 면 `why` 를 그대로 전한다. 실행기 결과의 꼬인 모서리는 손자리가 **다시 뜨기**(닫힌 메시로 새로 씌움)로 없앤다 — 영수증의 `before` 가 고치기 전, 본 판정이 다시 뜬 뒤다.
- 프린트 영수증에서 사람에게 꼭 전할 것:
  - `thin_share` · `thin_bbox_mm` — 최소 굵기보다 가는 곳의 몫과 자리(mm). 0 이 아니면 「이 자리가 노즐 몇 줄 굵기라 약하거나 안 나온다」고 말하고, 그림을 굵게 다시 그릴지 묻는다.
  - 결정 목록의 `orientation` — 다른 방향이 받침을 크게 줄이면 **제안만** 있다(설정은 지금 방향 그대로). 돌릴지는 사람이 정한다.
  - 썰기 `notes` — 「다시 썰면 실패」가 있으면 뱀부 스튜디오 화면에서 「플레이트 슬라이스」로 확인하고 출력하라고 전한다.
- 출력 시작은 사람이 누른다. 손자리는 프린터로 보내지 않는다.
- `not_done` 은 못 한 것이다. 빼지 말고 전한다.
- 512 로 굽고, 얼굴 · 무늬가 더 또렷해야 할 때만 1024(몇 배 오래)로 다시 굽는다.

## 5. 하지 않는 것

- 굽는 동안 같은 그래픽카드로 다른 큰 일을 시키지 않는다(앱은 입력창을 흐리게 잠근다).
- 손자리 결과 폴더 밖으로 파일을 옮기거나 덮어쓰지 않는다.
- 미리보기를 보지 않고 「잘 나왔다」고 말하지 않는다.

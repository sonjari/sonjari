# 사이트 레시피

사이트 하나를 다루는 데 필요한 지식을 **파이썬이 아니라 이 폴더의 JSON**으로 적는다.
새 사이트를 붙일 때 코드를 고칠 일이 없어야 한다는 게 목적이다.

## 왜 이렇게 하나

밑에 깔린 것(프레임 탐색·팝업 처리·클릭 회복·증거 검증)은 전부 사이트와 무관해졌다.
사이트마다 진짜로 다른 건 몇 가지뿐이다 — 어느 주소가 시작점인지, 어느 셀렉터가 목표인지,
무엇이 "됐다"의 증거인지. 그것만 여기 적는다.

## 형식

```jsonc
{
  "name": "사이트키",
  "hosts": ["example.com"],          // 여길 벗어나는 주소는 열지 않는다 (안전선)
  "urls":    { "editor": "https://example.com/write" },
  "targets": { "save": [".btn_save", "button:has-text('저장')"] },  // 앞이 정확한 것, 뒤가 대비책
  "actions": {
    "save_draft": {
      "risk": "L2",                  // L2는 화면 승인이 있어야 실행된다
      "steps": [
        { "do": "open", "url_key": "editor" },
        { "do": "dismiss" },
        { "do": "fill", "target": "title", "value": "{title}" },
        { "do": "click", "target": "save",
          "expect": { "kind": "number_increases", "selector": ".btn_save" } }
      ]
    }
  }
}
```

`_`로 시작하는 키(`_why`, `_note_*`)는 무시된다 — 왜 그렇게 했는지 적는 자리다.

### 단계

| do | 하는 일 |
|---|---|
| `open` | `url` 또는 `url_key`로 이동. hosts 밖이면 거부 |
| `find` | 셀렉터를 찾아 ref로 잡아둔다 (`as`로 이름 붙여 나중에 `$이름`으로 재사용) |
| `fill` | 입력. 비밀번호·파일 입력은 브라우저 계층이 막는다 |
| `click` / `press` | 누른다. **expect 필수** |
| `dismiss` | 가로막는 창 정리. **부정 버튼만** 눌린다 |
| `verify` | 지금 화면에 문구·요소가 있는지 확인 |
| `wait` | `ms`만큼 기다림 |

### expect (증거)

| kind | 의미 |
|---|---|
| `number_increases` | selector가 보여주는 숫자가 올라감 (저장 개수 같은 것) |
| `count_increases` | selector에 걸리는 요소 수가 늘어남 |
| `text_appears` / `text_disappears` | value 문구가 나타남/사라짐 |
| `appears` / `disappears` | selector 요소가 나타남/사라짐 |
| `url_changes` | 주소가 바뀜 |

## 지켜지는 것 (규칙, 관행 아님)

- **바꾸는 클릭에 `expect`가 없으면 불러올 때 거부된다.** 증거 없이 "됐습니다"라고 말하지 않기 위해서다.
- **`dismiss`는 부정 버튼만 누른다.** 확인이 필요한 창은 문구를 알리고 멈춘다.
- **`hosts` 밖으로는 안 간다.**
- **증거를 못 읽으면(`unverified`) 거기서 멈춘다.** 자동 재시도는 하지 않는다 —
  클릭은 먹었는데 확인만 못 읽었을 수 있고, 그러면 두 번 저장된다.

## `drafts/` — 자비스가 써 둔 초안

`drafts/` 안의 파일은 **아직 실행되지 않는다.** 로더가 `*.json` 한 겹만 읽으므로
하위 폴더는 잡히지 않는다. 폴더 하나가 초안과 확정의 경계다.

| 도구 | 등급 | 무엇 |
|---|---|---|
| `site_draft_recipe` | L1 | 자비스가 초안을 쓴다. **지금 화면에 걸리는 셀렉터만** |
| `site_review_draft` | L0 | 초안을 사람이 읽게 보여준다 |
| `site_promote_draft` | L2 | 확정 — `recipes/` 로 올린다. 화면 승인 필요 |

**초안 쓰기를 연 이유.** 막힌 그 순간의 자비스는 이미 진짜 화면을 보고 있다.
셀렉터를 지어낼 필요가 없는 자리인데, 관찰한 것을 JSON 으로 옮겨 적을 손이 없었다.

**확정을 사람이 하는 이유.** 레시피는 실행될 때 감시를 덜 받는다 — `site_run` 한 번에
절차가 통째로 돈다. 그럴듯한데 엉뚱한 것을 누르는 레시피는 레시피가 없는 것보다 나쁘다.

**초안이 거부되는 경우** (전부 쓰기 전에 걸린다)
- 넘긴 셀렉터가 지금 화면에서 하나도 안 걸림 → 무엇이 안 걸렸는지 이름을 대며 거부
- 바꾸는 클릭에 `expect` 없음 → 확정본과 같은 규칙
- `hosts` 비었거나, steps 가 없는 target 을 가리킴

덮어쓸 때는 예전 것을 `drafts/<이름>.replaced-<시각>.json` 으로 남긴다.

## 주의

- `naver_blog.json`은 실전 성공한 절차를 데이터로 옮긴 것이지만, **기존 `naver_blog_*` 도구를
  아직 대체하지 않는다.** 그쪽은 승인 흐름(prepare→commit)이 붙어 있어 따로 검증이 필요하다.
- 셀렉터는 추측하지 말 것. `browser_probe_frames`로 실제 DOM을 먼저 읽어라 —
  추측한 셀렉터가 이틀을 태웠다.
